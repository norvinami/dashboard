# Краткая инструкция

## Как открыть дашборд

1. В браузере откройте https://crm.bavaria-pavlodar.kz/ и войдите в свой аккаунт Битрикса.
2. В той же вкладке откройте https://crm.bavaria-pavlodar.kz/dashboard-oksana-v1/.
3. Если приложение уже зарегистрировано администратором портала, его также можно открыть из меню Битрикса. Регистрация описана в [BITRIX-APP.md](BITRIX-APP.md).

Доступ разрешён сотрудникам ID **5** и **405**. Оба сотрудника видят в дашборде данные Оксаны (ID 5), включая те, которые самому 405 недоступны в CRM. Это режим только просмотра. Права самого 405 в Битриксе не расширяются; по ссылке на сделку возможен отказ, если у него нет доступа к этой записи. Отдельного логина и пароля у дашборда нет.

## Где админка

Административная часть Битрикса: https://crm.bavaria-pavlodar.kz/bitrix/admin/ — открывается под аккаунтом с правами администратора Битрикса. Разрешение смотреть дашборд само по себе не даёт прав администратора. Отдельной админки дашборда и экрана управления доступом пока нет; список допуска находится в `bootstrap.php`.

## Где находятся файлы

- На рабочем сервере: `/home/bitrix/www/dashboard-oksana-v1/`.
- Копия репозитория для обновлений: `/home/bitrix/bavaria-dashboard-stage/`.
- Исходники: https://github.com/norvinami/dashboard (ветка `main`).
- `view.php` — внешний вид и фильтры; `api.php` — чтение показателей; `bootstrap.php` — вход и список допущенных сотрудников; `read-access.php` — фиксированный источник данных ID 5. Остальные PHP-файлы обслуживают отдельные блоки.

Не заменяйте файлы самого Битрикса и не редактируйте рабочую папку для обычного обновления.

## Как обновить

В PowerShell на своём компьютере выполните:

```powershell
ssh bitrix@31.3.209.165
```

Введите SSH-пароль. При вводе символы не отображаются — это нормально. Пароль от SSH и пароль от аккаунта Битрикса могут отличаться. При запросе о новом ключе сервера сверяйте отпечаток с администратором сервера; не подтверждайте изменившийся ключ вслепую.

Когда появится приглашение `[bitrix@crm ~]$`, выполните:

```bash
(
  set -e
  git -C /home/bitrix/bavaria-dashboard-stage pull --ff-only
  bash /home/bitrix/bavaria-dashboard-stage/deploy-dashboard.sh
)
```

Дождитесь сообщения «Дашборд обновлён». Если возникла ошибка, не продолжайте ручное копирование файлов — сохраните текст ошибки для разбора. Скрипт проверяет PHP и тесты, делает резервную копию прежнего дашборда и печатает её расположение вне папки сайта.

В браузере нажмите **Ctrl+F5**. Завершить SSH-сеанс можно командой `exit`.

## Как читать показатели

- Две даты сверху — период **создания** лидов и сделок. Статусы и значения полей используются текущие.
- В «Воронках» кнопка «Все» снимает все галочки, если отмечены все, иначе отмечает все. Затем нажмите «Применить».
- «Источники клиентов» учитывают сделки всех выбранных воронок, включая сервис.
- Во вкладке «Сервис» считаются сделки сервисной воронки, созданные за период. Все показатели, таблица и причины отказа учитывают выбранных ответственных, статус и поиск. Если ответственные не отмечены, учитываются все доступные.
- «Отложенные» — сделки со значением **«Отложил покупку»** пользовательского поля **«СТАТУС СДЕЛКИ»**; стадия сделки это поле не подменяет.
- Главный отчёт «Дела по сделкам» учитывает выбранные воронки и сделки, созданные за период; состояние незавершённых CRM-дел — на сегодня. Одна сделка показана один раз по ближайшему доступному сроку.
- Группы дел не пересекаются: до сегодня — просрочено; сегодня; после сегодня до воскресенья — неделя; оставшаяся часть текущего месяца — месяц. Неделя может переходить в следующий месяц. Без срока и позже месяца выводятся отдельно. «Нет дела» означает отсутствие доступных незавершённых дел, а не отсутствие любых дел в истории.
- При нескольких причинах отказа у одной сделки она входит в каждую причину один раз; процент каждой причины считается от общего числа проваленных, поэтому сумма может превышать 100%.
- Прочерк с предупреждением о поле означает, что его настройку не удалось однозначно найти. Это не нулевое значение.

## Если «Обращения из лидов» показывает нули

Откройте «CRM → Лиды» **под аккаунтом Оксаны (ID 5)**, установите тот же период создания и сбросьте остальные фильтры; проверьте завершённые и сконвертированные лиды. В общем режиме права пользователя 405 на лиды не определяют содержимое графика. Если данных также нет под Оксаной, администратор должен проверить её права на чтение лидов и наличие лидов в CRM. В простом режиме CRM сделки могут существовать без лидов.

Если доступны только другие причины обращения, отметьте их в графике. Ссылка «Проверить доступные количества» покажет ID вошедшего сотрудника, источник данных ID 5 и диагностические количества/дату, без клиентских данных. Оксана должна оставаться активным пользователем Битрикса; иначе API выдаст ошибку источника. Пароль Оксаны сотруднику 405 не нужен.
