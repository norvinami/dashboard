# Бавария: дашборд Bitrix

PHP-страница только для авторизованного пользователя ID 5 (Оксана Шлегель). CRM, лиды и задачи читаются с её правами, без сервисного администратора, пароля, вебхука или `NOT_CHECK_PERMISSIONS`. Все входы защищены; ответы посылают `no-store`. Общий кэш веб-сервера/CDN для страницы недопустим.

Страница: `/dashboard-oksana-v1/`. Семь PHP-файлов: `bootstrap.php`, `index.php`, `api.php`, `view.php`, `task-data.php`, `date-range.php`, `lead-data.php`. Node.js и отдельный сервер приложению не нужны. Оформление использует Google Fonts (Inter), при недоступности — запасной шрифт.

## Даты

Два календаря «С» и «По», обе даты включаются целиком. По умолчанию — с начала текущего месяца до сегодняшнего дня. Несуществующие даты и обратный диапазон отклоняются. При смене дат сохраняются выбранные причины обращения, результаты и воронки. Для сравнения сделок берётся непосредственно предшествующий период такой же длины в днях. Даты интерпретируются в часовом поясе PHP/Bitrix сервера; в URL используются `from` и `to` в формате `YYYY-MM-DD`.

Сделки отбираются по дате создания. За выбранный и предыдущий периоды вместе допускается до 5000 доступных сделок: при превышении вместо неполных показателей выводится ошибка. Задачи — текущее состояние, независимо от периода; сервер считает полные итоги, списки выдаются по 50 записей.

## График лидов

Отдельный график «Обращения из лидов», два направления: «Покупка автомобиля» и «Сервис». Состав обращений определяется полем лида, а не воронкой сделки. Фильтр причины обращения и фильтр результата относятся к этому графику; общий фильтр воронок относится к сделкам. Фильтр результата скрывает остальные сегменты, но не меняет знаменатель конверсии.

Поле-список `CRM_LEAD` определяется по единственной русской подписи «Причина обращения», значения перечисления — по подписям «Покупка автомобиля» и «Сервис». Код UF и ID значений не угадываются. Отсутствие или неоднозначность настройки выводит ошибку только в блоке лидов; остальные блоки продолжают работу.

Выбранный период относится к **дате создания лида**. Используются текущие статусы и текущая причина обращения. Исторические изменения причины не восстанавливаются и новые поля/обработчики в Bitrix не создаются.

- **Целевой:** лид успешен (`S`) и связан через `LEAD_ID` с доступной пользователю сделкой правильного направления: покупка авто → категория `0` («Продажа новых авто»), сервис → категория `7`. Состояние самой сделки не влияет на факт квалификации лида. Сделка может быть создана позже выбранного периода.
- **Неуспешный:** лид имеет семантику отказа `F`.
- **В работе:** лид имеет семантику `P`; это не отказ.
- **Не подтверждено:** лид успешен, но доступная связь со сделкой правильной категории не найдена. Другая воронка или отсутствие прав на связанную сделку не подменяются отказом.

Один лид считается один раз, даже при нескольких связанных сделках. 10 лидов по покупке авто и один целевой дают 10% конверсии. Неуказанные и неоднозначные причины показываются отдельным числом и не распределяются произвольно между двумя направлениями. Лиды и связи со сделками читаются порциями с проверкой прав.

## Остальные показатели

Успех комиссионной сделки означает успех стадии, а не продажу автомобиля. Успех сервиса означает запись, а не выполненный ремонт. Суммы сделок — `OPPORTUNITY` в KZT, не поступления оплаты. При другой валюте выводится ошибка. Телефоны, поля автомобиля и заказ-наряды 1С не подключены. Пустые источники скрываются. Рабочие стадии воронки идут в порядке Bitrix, первые шесть непустых раскрываются отдельно, успешные и проваленные вынесены в итоги. История переходов не подключена.

## Обновление на сервере

Из SSH пользователя `bitrix`:

```bash
git -C /home/bitrix/bavaria-dashboard-stage pull --ff-only
bash /home/bitrix/bavaria-dashboard-stage/deploy-dashboard.sh
```

Если `git pull` завершился ошибкой, остановиться. Скрипт проверяет PHP-синтаксис и автономные тесты, готовит копию страницы с сохранением дополнительных пользовательских файлов, затем переключает только каталог дашборда. Полная резервная копия остаётся вне корня сайта по адресу, напечатанному скриптом. При неудачном переключении предыдущая версия восстанавливается автоматически. Источники Bitrix и записи CRM не меняются. Не копировать `.git`, тесты и shell-скрипт в корень сайта.

После обновления войти как Оксана, проверить обе даты, значения поля и показатели на небольшом известном наборе лидов. Сверять по исходным лидам и связанным сделкам, а не по дате создания сделки. Проверить другие аккаунты и приватное окно: ни страница, ни API не должны возвращать данные дашборда. Стандартная страница входа Bitrix допустима. Автономные тесты не проверяют реальную реализацию API и права рабочего Bitrix.

## Проверки

`php tests/tasks.php` проверяет 2607 искусственных задач: полные итоги, фильтры, курсорные страницы и передачу параметров прав.

`php tests/leads-and-dates.php` проверяет даты, високосные дни, границы суток, причины обращения, порции по 500 лидов, повторные сделки одного лида, нужную категорию, отказы и незакрытые лиды, конверсию за пределами периода создания лидов, неоднозначность поля и передачу параметров прав. Использует искусственный Bitrix API.

Локально выполнены PHP 8.2 (WebAssembly) lint и автономные тесты, браузерные проверки дат/графика/фильтров/экранирования/отказа API и тест переключения каталогов с восстановлением после ошибки. Проверка новых полей и цифр на рабочем сервере требует установки пользователем.
