# Бавария: первая интеграция с Bitrix

Статус: первая версия размещена пользователем на Bitrix. Устранение ограничения по задачам подготовлено; проверка обновления на сервере ещё требуется.

Пакет содержит пять PHP-файлов. Разместить в отдельном новом каталоге dashboard-oksana-v1 внутри корня сайта. Существующие файлы CRM не заменять. Все PHP-входы защищены проверкой сессии: только авторизованный пользователь ID 5. Данные читаются с его правами CRM и задач, без сервисного администратора, пароля, вебхука или NOT_CHECK_PERMISSIONS. Ответы не должны кэшироваться на уровне веб-сервера/CDN; PHP посылает no-store.

Внешняя зависимость оформления: Google Fonts (Inter); при недоступности используется запасной шрифт. Node.js и отдельный сервер приложению не нужны. Самостоятельно устанавливать пакеты Bitrix или менять настройки его авторизации не нужно.

Показатели относятся к сделкам, созданным за выбранный период, и их текущим стадиям. История переходов не подключена. Успешность определяется STAGE_SEMANTIC_ID; успешная комиссионная сделка обозначает успех стадии, а не продажу автомобиля. Все выбранные воронки кроме ID 7 показываются в блоке сделок; ID 7 — в блоке сервиса. Успех сервиса означает запись, не ремонт. Суммы — OPPORTUNITY в KZT, не оплата. При другой валюте отображается ошибка вместо некорректной суммы.

Лиды как отдельная сущность, телефоны клиентов, пользовательские поля автомобиля и заказ-наряды 1С ещё не подключены; отсутствие значений отображается явно. Задачи доступны по правам пользователя 5 и не фильтруются по воронкам. Данные обновляются при загрузке страницы. Ограничение: 5000 сделок за восемь месяцев; при превышении приложение отказывает в показе частичных цифр. Задачи читаются сервером порциями с проверкой прав; полные итоги считаются без лимита в 2000, списки выдаются по 50 записей. Сводки на главной странице и по сотрудникам не зависят от загруженной части списка. Для каждой страницы задач выполняется проход по доступным задачам; на очень больших объёмах может понадобиться оптимизация запросов.

Перед размещением выполнить PHP lint для каждого файла в распакованном каталоге. После размещения войти в Bitrix как Оксана и открыть /dashboard-oksana-v1/. Проверить ответ api.php в браузере и сверить показатели с CRM по тому же периоду создания и воронкам. Проверить другие аккаунты и приватное окно: ни index.php, ни api.php, ни view.php не должны возвращать данные/разметку дашборда. Возможна стандартная страница входа Bitrix. Проверить отсутствие общего веб-кэша. Если Bitrix API этой версии несовместим, записать текст ошибки, не менять платформу для обхода.

Локальная проверка: PHP-синтаксис парсером с версией 8.2; браузерные проверки JSON-загрузки, подсчётов, выбора воронок, задач без срока, ссылок в CRM, экранирования HTML, отсутствия запросов на запись и отказа API. Эти проверки используют искусственные данные и не подтверждают работу PHP/прав на сервере.

Откат: сначала убрать только созданный каталог из корня сайта, переместив его в /home/bitrix/dashboard-oksana-v1-disabled-<timestamp>. Это сохраняет файлы для диагностики. Никакие сделки или задачи пакет не меняет.

Обработчик проверен локально в PHP 8.2 (WebAssembly) на искусственных данных; проверка на рабочем Bitrix ещё требуется. Проверка обработчика без подключения к CRM: `php tests/tasks.php`. Тест использует 2607 искусственных задач, проверяет итоги, просрочку, фильтры, страницы и передачу параметров прав. Это не проверка реализации CTasks на рабочем сервере.
